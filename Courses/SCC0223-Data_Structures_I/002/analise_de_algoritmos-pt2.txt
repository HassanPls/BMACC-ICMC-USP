1. CONCEITOS E REVISÃO DE ANÁLISE ASSINTÓTICA
-------------------------------------------------------------------------------
- O custo de uma solução aumenta conforme o tamanho da entrada (n) cresce.
- A eficiência é representada por uma Função de Custo (complexidade computacional)
  que descreve a ordem de crescimento quando n tende ao infinito (n -> ∞).
- Caracteriza a complexidade de tempo independente do hardware/computador.
- Foca em operações dominantes (elementares), ex: número de comparações.

2. DEFINIÇÃO FORMAL DA NOTAÇÃO O (BIG-OH)
-------------------------------------------------------------------------------
- Limite Superior (Upper Bound): Uma função g(n) domina assintoticamente f(n)
  se existirem constantes positivas 'c' e 'n0' tais que:
      |f(n)| <= c * |g(n)|, para todo n >= n0

- Conjunto O(g(n)):
      O(g(n)) = { f(n) : existem c > 0 e n0 > 0 tais que 0 <= f(n) <= c*g(n), ∀ n >= n0 }

- Exemplos demonstrativos:
  * Exemplo 1: f(n) = 2n + 10 é O(n)?
    2n + 10 <= c * n  =>  (c - 2)n >= 10  =>  n >= 10 / (c - 2)
    Válido para c = 3 e n0 = 10. (Logo, é O(n)).
  * Exemplo 2: f(n) = n² é O(n)?
    n² <= c * n  =>  n <= c
    Impossível, pois 'c' precisa ser uma constante e 'n' cresce ao infinito.

- Outras notações citadas:
  * Ω (Omega): Limite inferior (lower bound).
  * Θ (Theta): Limite justo/estrito (tight bound).

3. HIERARQUIA E CARACTERÍSTICAS DAS FUNÇÕES
-------------------------------------------------------------------------------
- Constante [O(1)]: Operações executadas um número fixo de vezes.
- Logarítmica [O(log n)]: Típica de algoritmos que dividem problemas em subproblemas.
- Linear [O(n)]: Processa cada elemento da entrada uma quantidade fixa de vezes.
- Log-Linear / n-log-n [O(n log n)]: Divisão e conquista com combinação de soluções.
- Quadrática [O(n²)]: Laços aninhados (processamento em pares).
- Cúbica [O(n³)]: Três laços aninhados (ex: multiplicação de matrizes).
- Exponencial [O(a^n)]: Soluções de força bruta; impraticáveis.
- Fatorial [O(n!)]: Força bruta extrema (ex: n=20 -> 2,4x10^18 op; n=40 -> 8,2x10^47 op).

4. DICAS PRÁTICAS PARA ANÁLISE DE ALGORITMOS
-------------------------------------------------------------------------------
- Desprezar termos de menor ordem e fatores constantes.
- Usar a menor classe de funções simples possível (ex: O(n) em vez de O(2n) ou O(3n+5)).
- Repetições simples: Tempo do bloco interno * número de iterações.
- Repetições aninhadas: Análise de dentro para fora (multiplicação dos limites das iterações).
- Condicionais (if-else): Tempo do teste + o tempo do maior bloco (então/senão).
- Chamadas de subrotinas: Analisa-se a subrotina primeiro e incorpora seu custo ao chamador.
- Ressalva prática: Para entradas muito pequenas, constantes grandes podem impactar. 
  (Ex: 10^100 * n vs 10 * n log n).

5. EXERCÍCIOS E CÓDIGOS DISCUTIDOS
-------------------------------------------------------------------------------
A. Comparação: f(n) = n^(1,5) vs g(n) = n log n
   Dividindo por n: n^(0,5) vs log n. Como 'n' cresce mais rápido que qualquer 
   potência de log, g(n) = n log n é mais eficiente.

B. Análise de Laços Aninhados:
   01: inicialização de A e i
   02: enquanto (i < n) faça ...       -> O(n)
   03: para i = 1 até n faça           -\
   04:   para j = 1 até n faça         ---| -> O(n²)
   05:     A[i] = A[i] + (i * j)       -/
   Complexidade Total do Algoritmo: O(n²)

C. Função de Exponenciação Simples:
   int exp1(int a, int b) {
       int res = 1;
       while (b > 0) { res *= a; b -= 1; }
       return res;
   }
   Complexidade de Tempo em função do expoente 'b': O(b)
